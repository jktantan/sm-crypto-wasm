## 摘要（CSDN 摘要字段，约 120 字）

SM9 是标识密码：ID 就是公钥，不需要证书链。但网页端几乎找不到可用实现。本文拆解五个现实原因，并给出一个 AssemblyScript → WebAssembly 的完整实现：R-ate pairing、Fp12 扩域、Montgomery 域、固定基点 comb，以及签名 4.11ms / 验签 8.00ms / 密钥交换 19.6ms 的实测数据。

## 评论区预备回答

- **“为什么不用纯 JS？”** pairing 是 Fp12 扩域乘法的堆积；纯 JS 用 BigInt/数组模拟，开销大。本文不给纯 JS 倍数，因为没做全面基准；但 WASM 优化前验签也要 12.7ms。
- **“为什么只快 1.6–1.8×？”** 这是 Montgomery 域这一项优化的端到端收益；单次模乘是 1.82×。SM9 的耗时由 pairing 主导，域运算的收益会被 Miller loop / final exponent 的结构性成本摊薄。
- **“8ms 算快吗？”** 一次登录/验签可以接受；批量、高频场景仍需服务端或缓存。8ms 是 x86 桌面数据。
- **“为什么密钥交换要同一 KGC？”** SM9 是 IBC，Ppube 是信任锚；双方不属于同一 KGC 时，协议前提不成立。本项目 API 以 `ke` 为输入，示例里双方传同一个 `ke`。
- **“主私钥能放前端吗？”** 不建议。KGC 主私钥应留在服务端；前端最多持有用户私钥，并尽量缩短生命周期、避免导出。
- **“能过商密认证吗？”** 本库是算法实现，不替代测评和合规流程；请按行业要求评估。
- **“和 GmSSL 对得上吗？”** 签名 / 加密 / KEM / 密钥交换都有 GmSSL KAT 逐字节对拍；C3 用 HMAC-SM3(K2, C2)，KDF 输入取 C1 的 x||y 64B，这两处是互操作重点。
